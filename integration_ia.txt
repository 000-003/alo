2. KeylessAI – proxy OpenAI-compatible zéro clé

KeylessAI est un endpoint public qui traduit les appels OpenAI vers des LLM gratuits.

Configuration:

```bash
export OPENAI_API_BASE="https://keylessai.thryx.workers.dev/v1"
export OPENAI_BASE_URL="https://keylessai.thryx.workers.dev/v1"
export OPENAI_API_KEY="not-needed"
```

Test rapide:

```bash
curl https://keylessai.thryx.workers.dev/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model":"gpt-4o","messages":[{"role":"user","content":"Bonjour"}]}'
```

Avec le SDK OpenAI:

```python
from openai import OpenAI
client = OpenAI(
    base_url="https://keylessai.thryx.workers.dev/v1",
    api_key="not-needed"
)
response = client.chat.completions.create(
    model="gpt-4o",
    messages=[{"role": "user", "content": "Bonjour"}]
)
```

Fonctionnalités: aliasing de modèles, failover multi-fournisseur, cache, rate limiting, circuit breaker.

Limite: 100 000 requêtes/jour (free tier Cloudflare).

3. Architecture d'orchestration pour votre bot

Schéma:

```
Votre Bot → Couche Orchestrateur → Puter.js (500+ modèles) / KeylessAI (fallback)
```

Implémentation d'un routeur intelligent:

```javascript
async function orchestrator(prompt, model = "openai/gpt-4o") {
  try {
    // Tentative avec Puter.js d'abord
    return await puter.ai.chat(prompt, { model });
  } catch (error) {
    // Fallback sur KeylessAI si Puter.js échoue
    const fallbackClient = new OpenAI({
      baseURL: "https://keylessai.thryx.workers.dev/v1",
      apiKey: "not-needed"
    });
    const response = await fallbackClient.chat.completions.create({
      model: "gpt-4o",
      messages: [{ role: "user", content: prompt }]
    });
    return response.choices[0].message.content;
  }
}
```

Avec logique métier (ex: analyse de sentiment + action):

```javascript
async function botOrchestrator(userInput) {
  // 1. Analyse avec Puter.js
  const analysis = await puter.ai.chat(
    `Analyse le sentiment de: "${userInput}"`,
    { model: "google/gemini-2.5-flash" }
  );
  
  // 2. Décision basée sur l'analyse
  if (analysis.includes("positif")) {
    return await puter.ai.chat("Génère une réponse enthousiaste", {
      model: "anthropic/claude-sonnet-4-6"
    });
  } else {
    return await puter.ai.chat("Génère une réponse empathique", {
      model: "openai/gpt-4o"
    });
  }
}
```

Pour neutraliser les hallucinations dans votre orchestrateur, il ne suffit pas de choisir un modèle ; il faut verrouiller le système de sélection et imposer des gardes-fous post-génération. Voici les 5 niveaux de contrôle à implémenter.

---

1. Whitelist stricte (interdire les modèles fragiles)

Tous les modèles ne se valent pas. Les petits modèles (7B, 8B) et les versions "Flash" ou "Lite" non distillées sont les plus hallucinogènes. Imposez une whitelist dans votre orchestrateur.

Modèles à bannir définitivement :

· llama-3-8b, mistral-7b, gemini-1.5-flash (sur des raisonnements longs), gpt-3.5-turbo.
· Tous les modèles "uncensored" ou "ablated" (souvent dégradés).

Modèles à conserver (faible hallucination) :

· openai/gpt-4o / openai/gpt-4-turbo
· anthropic/claude-3.5-sonnet / claude-3.7-sonnet
· google/gemini-2.5-pro (excellent pour la logique)
· deepseek/deepseek-v3 (précis sur les faits)

Code de filtrage :

```javascript
const ALLOWED_MODELS = new Set([
  "openai/gpt-4o",
  "anthropic/claude-3.5-sonnet",
  "google/gemini-2.5-pro",
  "deepseek/deepseek-v3"
]);

async function safeOrchestrate(prompt, requestedModel) {
  // Forcer un modèle safe si le demandé est hors liste
  const model = ALLOWED_MODELS.has(requestedModel) 
    ? requestedModel 
    : "openai/gpt-4o"; // fallback par défaut
  
  return await puter.ai.chat(prompt, { model });
}
```

2. Paramètres de décodage « zéro créativité »

L'hallucination naît de la température. Pour un orchestrateur logique, utilisez des valeurs minimales.

Paramètre Valeur conseillée Effet
temperature 0.0 à 0.2 Élimine l'aléatoire, force le token le plus probable.
top_p 0.85 Coupe les queues de distribution aberrantes.
frequency_penalty 0.1 Évite les répétitions qui dégradent la cohérence.

Appel Puter.js avec paramètres :

```javascript
const response = await puter.ai.chat(prompt, {
  model: "openai/gpt-4o",
  temperature: 0.1,
  top_p: 0.85
});
```

---

3. Vérificateur de cohérence (Double Check)

Avant de renvoyer la réponse au bot, soumettez-la à un second modèle rapide (mais safe) pour validation. Cette technique réduit les hallucinations de ~40 %.

```javascript
async function hallucinationGuard(originalPrompt, firstAnswer) {
  const checkPrompt = `
    Vous êtes un validateur logique. La question initiale était : 
    "${originalPrompt}"
    
    La réponse proposée est : 
    "${firstAnswer}"
    
    Répondez uniquement par "VALID" si la réponse est logique et ne contient pas de données inventées.
    Répondez par "INVALID: raison" si elle contient des contradictions ou des faits non vérifiables.
  `;
  
  const validation = await puter.ai.chat(checkPrompt, {
    model: "google/gemini-2.5-flash", // rapide mais fiable
    temperature: 0.0
  });

  if (validation.includes("INVALID")) {
    // On régénère avec une instruction de prudence
    return await puter.ai.chat(
      `Répondez strictement à : "${originalPrompt}". Si vous ne savez pas, dites "Je ne dispose pas de cette information."`,
      { model: "anthropic/claude-3.5-sonnet", temperature: 0.0 }
    );
  }
  return firstAnswer;
}
```

---

4. Mode "Réflexion" (Chain-of-Thought contrainte)

Forcez le modèle à afficher ses étapes de raisonnement avant la conclusion. Cela expose les incohérences et permet à l'orchestrateur de les détecter.

Prompt systématique :

```javascript
const SAFE_PROMPT_TEMPLATE = `
  Instructions strictes :
  1. Décomposez le problème en étapes logiques (max 3 points).
  2. Si une étape repose sur une hypothèse non vérifiée, mentionnez "HYPOTHÈSE".
  3. Ne concluez que si toutes les étapes sont validées.
  4. Format final : "RAISONNEMENT : ... | CONCLUSION : ..."

  Question : ${userPrompt}
`;
```

---

5. Gestion du "Je ne sais pas" (réduction du biais de confirmation)

L'hallucination est souvent due à l'obligation implicite de répondre. Injectez dans le système un prompt explicite d'abstention.

```javascript
const SYSTEM_PROMPT = `
  Vous êtes un moteur logique. 
  - Si la réponse n'est pas contenue dans votre contexte ou si vous n'êtes pas certain à 95%, répondez EXACTEMENT par : "INFO_INDISPONIBLE".
  - Ne faites jamais de suppositions créatives.
  - Ne comblez jamais les lacunes avec des données inventées.
`;
```

Résumé de l'architecture finale pour votre orchestrateur

```
Requête utilisateur 
    ↓
[1. Whitelist] → Forcer modèle safe (GPT-4o / Sonnet)
    ↓
[2. Prompt Système] → Injection de l'abstention + prompt réflexif
    ↓
[3. Paramètres] → Température = 0.0, Top_p = 0.85
    ↓

    ↓

    ↓

```

Avec ce pipeline, même si l'un des modèles sous-jacents (via Puter.js ou KeylessAI) a tendance à halluciner, votre couche d'orchestration écrase ce comportement par la force des contraintes et du double arbitrage, rendant le système fiable pour une logique métier.
